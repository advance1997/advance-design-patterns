# 实践约定

## 课程来源

实践推进必须遵循《01-1｜设计模式专项》的原始教学顺序。
只有用户明确指定时才能调整，不以仓库的模式分类或助手建议替代课程顺序。

后续新增示例统一采用催收金融业务背景，这是用户明确指定的场景改编。
保留课程的设计问题和演进顺序，在 README 区分课程要点与工程化补充；
已完成的支付和物流实践不自动重写。仅使用虚构案件和模拟客户端，
不得接入真实客户资料、短信、外呼或真实资金操作；教学参数不作为监管规则。

Spring 实践使用兼容 Java 8 的 Framework 5.3.39，仅用于学习；
旧版本线不作为生产选型建议。Spring 依赖只由需要的独立叶子模块声明。

后续所有实践必须先核对《01-1｜设计模式专项》的对应示例和业务场景。
每个模式 README 记录来源、采用的场景和工程化补充范围；来源不可读时，
先获取对应内容，不擅自用其他场景替代。现有工厂模式的物流示例是早期实现，
尚未完成课程示例对齐，不把它标记为已核对。

Git 提交说明使用中文，正文描述具体修改与验证；作者名称使用 `advance`。

## 执行路径可视化

输出正文使用详细中文；类名、方法名、参数标识保留源码中的英文定义。
异常提示同样使用中文，并说明失败步骤或校验字段。

## 中文注释规范

遵循阿里巴巴 Java 开发手册的注释约定：类、接口、枚举、成员及方法使用
Javadoc 描述职责与契约；说明参数含义、单位、返回值、异常及扩展边界，
避免只复述方法名。注释放在注解之前；方法重写保留 Override。
类型文档统一标记 `@author advance`，时间使用 `@since yyyy-MM-dd HH:mm:ss`
（Asia/Shanghai）。数据对象使用 Java 8 普通类，构造方法及 getter 分别说明字段含义。
时间表示注释建立时间，后续修改不批量刷新历史时间。
控制台路径用于教学，不改变版本隔离规则和业务执行顺序。

后续实践在关键入口、工厂创建、具体实现、模板步骤/钩子及异常分支添加
`System.out.println`，采用“[模式/版本] 类或角色 ---> 步骤”的格式。
正常和异常测试都应让读者看清执行路径。每个测试方法的中文 Javadoc
必须说明输入、期望值、预期路径或异常；方法中直接打印实际结果供人工对照。
JUnit 只负责发现和执行测试，不使用断言框架、参数化测试、Lambda、方法引用、
Consumer 或 Function。客户端与失败场景使用具名普通模拟类，每个版本独立维护。
预期异常使用 try/catch 打印；未抛出时必须明确打印“未抛出异常，请对照期望检查”。
测试执行成功不等于实际结果已自动验证。全部源码必须兼容 JDK 1.8。
只输出步骤与必要的错误说明，不输出密钥、支付凭据或完整请求。
本项目使用控制台输出辅助学习，生产工程应使用结构化日志。

## 分层方式

目录按“模式类型 → 具体模式 → 推演版本”组织。类型层和模式层只聚合模块，不放业务代码；只有版本模块包含源码和测试。

Java 包名使用以下格式：

```text
com.advance.patterns.<类型>.<模式>.v<版本>
```

例如：

```text
com.advance.patterns.creational.factorymethod.v3
```

## 版本语义

- `v1-naive`：最直接的实现，用于暴露变化点与耦合。
- `v2-refactor`：提取创建职责或必要抽象，展示过渡方案。
- `v3-pattern`：完整应用目标设计模式。
- 后续版本按需要增加，但必须说明新增版本解决的问题。

## 独立性规则

1. 版本模块不得依赖同一模式的其他版本。
2. 不创建共享业务代码模块；领域对象也由各版本分别持有。
3. 新版本建立后，旧版本原则上只修复自身错误，不追随新版本重构。
4. 每个版本必须拥有自己的测试，并可以通过该版本的 `pom.xml` 单独运行。
5. 父项目可以统一 Java、测试框架和插件版本，但不能提供业务实现。

## 实践记录

每个模式的 README 至少记录：

- 示例业务场景；
- 每个版本的结构和问题；
- 相邻版本间发生的变化；
- 模式的收益、代价与适用边界；
- 全量和单版本测试命令。
