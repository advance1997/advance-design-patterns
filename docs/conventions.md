# 实践约定

## 课程来源

后续所有实践必须先核对《01-1｜设计模式专项》的对应示例和业务场景。
每个模式 README 记录来源、采用的场景和工程化补充范围；来源不可读时，
先获取对应内容，不擅自用其他场景替代。现有工厂模式的物流示例是早期实现，
尚未完成课程示例对齐，不把它标记为已核对。

Git 提交说明使用中文，正文描述具体修改与验证；作者名称使用 `advance`。

## 分层方式

目录按“模式类型 → 具体模式 → 推演版本”组织。类型层和模式层只聚合模块，不放业务代码；只有版本模块包含源码和测试。

Java 包名使用以下格式：

```text
com.advance.patterns.<类型>.<模式>.v<版本>
```

例如：

```text
com.advance.patterns.creational.factorymethod.v3
```

## 版本语义

- `v1-naive`：最直接的实现，用于暴露变化点与耦合。
- `v2-refactor`：提取创建职责或必要抽象，展示过渡方案。
- `v3-pattern`：完整应用目标设计模式。
- 后续版本按需要增加，但必须说明新增版本解决的问题。

## 独立性规则

1. 版本模块不得依赖同一模式的其他版本。
2. 不创建共享业务代码模块；领域对象也由各版本分别持有。
3. 新版本建立后，旧版本原则上只修复自身错误，不追随新版本重构。
4. 每个版本必须拥有自己的测试，并可以通过该版本的 `pom.xml` 单独运行。
5. 父项目可以统一 Java、测试框架和插件版本，但不能提供业务实现。

## 实践记录

每个模式的 README 至少记录：

- 示例业务场景；
- 每个版本的结构和问题；
- 相邻版本间发生的变化；
- 模式的收益、代价与适用边界；
- 全量和单版本测试命令。
