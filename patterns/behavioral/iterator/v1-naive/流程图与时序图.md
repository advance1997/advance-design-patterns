# 迭代器模式：v1-naive 流程图与时序图

本图对应版本说明：AssignmentService` 使用两层下标循环访问 `List<List<CaseInfo>>；空组可被自然处理，但业务服务了解分组结构，存储结构变化会影响遍历代码。

## 代码流程图

```mermaid
flowchart TD
    A[AssignmentTest.shouldAssignCasesByNestedLoops 测试入口]
    A --> B[AssignmentService.assignAll 业务入口]
    C[CaseInfo.getCaseId]
    B --> C
    Z[返回测试用例并打印实际路径]
    B -. 调用完成 .-> Z
    C -. 调用完成 .-> Z
```

## 代码时序图

```mermaid
sequenceDiagram
    participant Test as AssignmentTest
    participant Entry as AssignmentService
    participant Output as 测试输出
    participant Part1 as CaseInfo
    Test->>Entry: assignAll()
    Entry->>Part1: getCaseId()
    Part1-->>Entry: 返回处理结果
    Entry->>Output: 打印执行路径与期望结果
    Output-->>Test: 输出实际结果
    Entry-->>Test: 返回业务结果
```

## 阅读提示

- 先从 `AssignmentTest.shouldAssignCasesByNestedLoops()` 进入，再沿图中的真实类名和方法名阅读源码。
- 本版本的模式关注点：迭代器封装集合遍历状态，使调用者无需了解集合内部组织。
- 条件分支与返回细节请结合图中方法源码和同目录测试用例观察。
