# 命令模式：v2-pattern 流程图与时序图

本图对应版本说明：PauseCallCommand`、`ReassignCommand` 实现统一接口，由 `CommandInvoker` 排队后触发；调用者与操作实现解耦；命令对象持有 Receiver，适合同进程经典模式。

## 代码流程图

```mermaid
flowchart TD
    A[CommandTest.shouldQueueCommandsAndExecuteLater 测试入口]
    A --> B[CommandInvoker.submit 业务入口]
    C[PauseCallCommand.getCommandId]
    B --> C
    D[ReassignCommand.getCommandId]
    B --> D
    E[ResumeCallCommand.getCommandId]
    B --> E
    OP1[CaseActionService.stateOf 后续测试操作]
    B --> OP1
    OP2[CommandInvoker.executeAll 后续测试操作]
    B --> OP2
    Z[返回测试用例并打印实际路径]
    B -. 调用完成 .-> Z
    C -. 调用完成 .-> Z
    D -. 调用完成 .-> Z
    E -. 调用完成 .-> Z
```

## 代码时序图

```mermaid
sequenceDiagram
    participant Test as CommandTest
    participant Entry as CommandInvoker
    participant Output as 测试输出
    participant Part1 as PauseCallCommand
    participant Part2 as ReassignCommand
    participant Part3 as ResumeCallCommand
    participant Part4 as CaseActionService
    Test->>Entry: submit()
    Entry->>Part1: getCommandId()
    Part1-->>Entry: 返回处理结果
    Entry->>Part2: getCommandId()
    Part2-->>Entry: 返回处理结果
    Entry->>Part3: getCommandId()
    Part3-->>Entry: 返回处理结果
    Test->>Part4: stateOf() 后续操作
    Part4-->>Test: 返回处理结果
    Test->>Entry: executeAll() 后续操作
    Entry-->>Test: 返回处理结果
    Entry->>Output: 打印执行路径与期望结果
    Output-->>Test: 输出实际结果
    Entry-->>Test: 返回业务结果
```

## 阅读提示

- 先从 `CommandTest.shouldQueueCommandsAndExecuteLater()` 进入，再沿图中的真实类名和方法名阅读源码。
- 本版本的模式关注点：命令将操作请求封装为对象，使提交者与具体执行过程解耦。
- 条件分支与返回细节请结合图中方法源码和同目录测试用例观察。
