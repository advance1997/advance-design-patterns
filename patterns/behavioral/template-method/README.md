# 模板方法：支付处理流程

## 来源与实践范围

依据《01-1｜设计模式专项》同名历史会话的大纲：
“阶段 1 → 模板方法模式”列出支付处理流程、固定骨架与可变步骤、
抽象方法与钩子、前置/执行/后置/异常处理；
“阶段 10 → Version 4”要求抽取支付公共骨架和渠道差异步骤。
会话中的初始示例使用支付宝、微信支付，分别处理元金额/渠道协议和不同响应字段。

来源会话标识：`01a0ba95-6029-74e0-a6e2-c68184b4d5db`；
大纲回合：`01a0ba95-6670-7ed0-8d27-9b2279bc770d`。
本次读到了该历史会话的大纲和初始支付示例；新版 ChatGPT 会话返回的正文只有内容引用，
未据此声称逐字复刻后续模板方法讲义。

本实践是基于上述场景的可运行工程化补充。网关接口、流程事件和测试替身是教学简化，
不连接真实支付平台、数据库或 Spring。金额转换、异常路径和钩子测试为本仓库补充。

## 分层与版本

| 模块 | 问题与变化 | 阅读入口 |
| --- | --- | --- |
| v1-naive | 支付宝和微信各自复制校验、调用、成功、失败、完成流程 | service/AlipayPayment、WechatPayment |
| v2-refactor | PaymentSteps 复用公共步骤，但每个渠道仍能遗漏或重排步骤 | service/PaymentSteps |
| v3-pattern | AbstractPaymentTemplate 的 final pay() 唯一维护流程顺序 | service/AbstractPaymentTemplate |

每个版本是独立 Maven 叶子模块，包前缀分别为
`com.advance.patterns.behavioral.templatemethod.v1`、`v2`、`v3`。
各自的 domain、gateway、service、测试完全独立，只有构建配置继承根 POM。

## 稳定点和变化点

稳定骨架：校验 → 前置 → 渠道执行 → 后置 → 成功；执行区发生异常时记录失败并原样抛出，
finally 记录完成。入口校验失败直接拒绝，不进入渠道调用区。

V3 中：
- 模板方法：`final pay()`，子类不能覆盖整个算法。
- 必选抽象步骤：`doPay()`，各渠道调用自己的客户端并转换结果。
- 可选钩子：`beforePay()`、`afterPay()`，默认空实现。
- 支付宝：金额为元，成功码 10000，提取 tradeNo。
- 微信：元精确转换成 long 类型的分，读取 success 和 transactionId。
- null 响应、失败响应或空交易号均不视为成功。

`Consumer<String>` 仅用于观察流程，约定为不抛异常的教学记录器；
它不是可靠审计、事务提交或订单状态存储。
实现不在实例中保存请求，但并发使用还要求注入的客户端和记录器自身线程安全。

## 阅读与验证

先对比 V1 两个 pay()，观察增加步骤要修改几处；再看 V2 为什么仍可能漏调用；
最后看 V3 两个渠道如何只保留差异步骤。TemplateHooksTest 展示自定义钩子。

在仓库根目录，使用 JDK 21：
```bash
./mvnw test
./mvnw -f patterns/behavioral/template-method/pom.xml test
./mvnw -f patterns/behavioral/template-method/v3-pattern/pom.xml test
```

三个版本分别测试金额/响应转换、成功顺序、拒绝响应、协议异常、网关超时、
非法输入阻止调用。V3 额外验证钩子顺序、前置失败、后置失败、空返回值及 final 约束。

## 取舍与边界

模板方法适合流程稳定、部分步骤变化；策略适合整体算法替换。
V2 的公共助手不是模板方法，因为它不拥有执行顺序。
V3 以继承交换流程一致性，代价是子类受父类契约约束；不同业务流程不要硬塞进同一个父类。
final 只能约束入口覆盖，不能阻止子类在扩展步骤中做不合理的事情。

课程还提出回调式模板：固定流程可以通过组合接收执行回调，
例如 JdbcTemplate、TransactionTemplate 的使用方式；这不是要求每个使用者都继承模板。
本次三个版本聚焦继承式模板，回调式与 Spring 接入留作后续独立演进。

真实支付通常异步确认。这里模拟同步确认，不把“平台已受理”当作“已到账”。
渠道成功后的后置失败、超时都可能意味着结果未知，不自动重试、不声称回滚外部支付。
持久化、幂等、回调验签、对账补偿和事务边界需另行实现。
