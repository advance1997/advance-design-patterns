# 责任链模式：v2-refactor 流程图与时序图

本图对应版本说明：提取 PermissionRule、ContactWindowRule；规则职责独立，但服务仍负责每个分支和下一步调用。

## 代码流程图

```mermaid
flowchart TD
    A[OutboundChainTest.allowAfterAllRules 测试入口]
    A --> B[OutboundService.submit 业务入口]
    C[PermissionRule.allows]
    B --> C
    D[ContactWindowRule.allows]
    B --> D
    E[MockCallGateway.submit]
    B --> E
    Z[返回测试用例并打印实际路径]
    B -. 调用完成 .-> Z
    C -. 调用完成 .-> Z
    D -. 调用完成 .-> Z
    E -. 调用完成 .-> Z
```


## 阅读提示

- 先从 `OutboundChainTest.allowAfterAllRules()` 进入，再沿图中的真实类名和方法名阅读源码。
- 本版本的模式关注点：责任链让请求依次经过处理节点，由节点决定继续传递或短路。
- 条件分支与返回细节请结合图中方法源码和同目录测试用例观察。
