# 责任链模式：v3-pattern 流程图与时序图

本图对应版本说明：RuleHandler + 请求专用 RuleChain；节点决定是否传递，服务只启动链，不认识具体规则。

## 代码流程图

```mermaid
flowchart TD
    A[OutboundChainTest.allowAfterAllRules 测试入口]
    A --> B[OutboundService.submit 业务入口]
    B --> C[RuleChain.proceed 调度 PermissionHandler]
    C --> D[PermissionHandler.handle]
    D --> E{OutboundRequest.isPermitted?}
    E -->|否：短路返回| Z[返回 OutboundService.submit 并打印结果]
    E -->|是：调用 RuleChain.proceed| F[RuleChain.proceed 调度 ContactWindowHandler]
    F --> G[ContactWindowHandler.handle]
    G --> H{OutboundRequest.getHour 是否处于 9 到 18 点?}
    H -->|否：短路返回| Z
    H -->|是：调用 RuleChain.proceed| I[RuleChain.proceed 调用 MockCallGateway.submit]
    I --> Z
```

## 代码时序图

```mermaid
sequenceDiagram
    participant Test as OutboundChainTest
    participant Entry as OutboundService
    participant Output as 测试输出
    participant Chain as RuleChain
    participant Permission as PermissionHandler
    participant Contact as ContactWindowHandler
    participant Gateway as MockCallGateway
    participant Request as OutboundRequest
    Test->>Entry: submit()
    Entry->>Chain: proceed(request)
    Chain->>Permission: handle(request, chain)
    Permission->>Request: isPermitted()
    Request-->>Permission: true，继续传递
    Permission->>Chain: proceed(request)
    Chain->>Contact: handle(request, chain)
    Contact->>Request: getHour()
    Request-->>Contact: 10，处于允许窗口
    Contact->>Chain: proceed(request)
    Chain->>Gateway: submit(request)
    Gateway-->>Chain: 模拟申请通过
    Chain-->>Contact: 返回处理结果
    Contact-->>Permission: 返回处理结果
    Permission-->>Entry: 返回处理结果
    Entry->>Output: 打印执行路径与期望结果
    Output-->>Test: 输出实际结果
    Entry-->>Test: 返回业务结果
```

## 阅读提示

- 先从 `OutboundChainTest.allowAfterAllRules()` 进入，再沿图中的真实类名和方法名阅读源码。
- 本版本的模式关注点：责任链让请求依次经过处理节点，由节点决定继续传递或短路。
- 条件分支与返回细节请结合图中方法源码和同目录测试用例观察。
