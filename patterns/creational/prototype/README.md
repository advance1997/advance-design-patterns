# 原型：催收人工复核任务模板复制

## 来源与约定

依据《01-1｜设计模式专项》阶段 2 大纲，会话
`01a0ba95-6029-74e0-a6e2-c68184b4d5db`，
大纲回合 `01a0ba95-6670-7ed0-8d27-9b2279bc770d`。
按用户的新要求，将课程设计要点改编为催收金融业务；下述类名、数据和细节是
本仓库工程化补充，不宣称是课程原始案例。

所有案件编号、配置和流程均为虚构。只模拟人工复核，不发送短信、不外呼，
不查询真实客户资料、不决定信用待遇或采取法律行动。教学参数不代表真实监管规则。

采用 Java 8、普通类与直接方法调用。每个版本独立持有源码和测试，
不共享业务类，不依赖其他版本。Javadoc 使用作者 advance 和上海时区创建时间。
测试仅由 JUnit 发现和运行，上方标注期望，直接打印实际值，不使用断言或函数式回调。
预期异常打印类型和信息，未抛出则提示人工核查；绿色测试不等于输出已被自动证明正确。

课程对应浅拷贝与深拷贝、Cloneable 局限、复制构造器和复制成本。

## 版本与阅读顺序

| 版本 | 实现 | 预期结果 |
| --- | --- | --- |
| v1-naive | 调用方用原列表手工创建新模板 | 两个模板共享列表及步骤；副本修改污染原模板 |
| v2-refactor | Object.clone + new ArrayList | 对象和列表不同，但可变 ReviewStep 仍相同 |
| v3-pattern | 显式复制构造器，逐项复制 ReviewStep | 副本与原模板的可变步骤互不影响 |

包前缀为 `com.advance.patterns.creational.prototype.v1/v2/v3`。
ReviewStep 保存“材料核对”等人工步骤及 reviewed 状态，不是客户信用或风险评分。

## 重点观察

- 两个列表不是同一个引用，不等于深拷贝；还要检查可变元素。
- V1/V2 的反例有意允许共享状态。测试期望原模板也变为 true，是在展示缺陷，不是正确生产行为。
- V2 的 Cloneable 只是标记接口，Object.clone 做字段级浅拷贝，
  不自动复制对象图；本例额外复制了列表容器，但故意不复制元素。
- V3 不使用 Cloneable，复制构造器清楚地列出需要复制的可变字段。
- V3 构造时复制输入、读取时返回深拷贝只读列表：
  外部即使修改返回列表里的步骤对象，也不会修改内部状态。
- markReviewed 明确修改当前模板自己的步骤，不隐式修改别的模板。
- copy 保留当前状态，不是“创建一份未复核任务”；如果需要重置，应单独定义业务操作。
- null、空步骤、空名称、空元素和越界位置均有显式错误路径。

## 不要混淆

GoF 原型模式通过复制已有对象得到新对象；
Spring prototype scope 是每次向容器请求时创建实例，并不意味着 clone。
本例与 factory-ioc 的 prototype 会话职责不同，也没有共享业务代码。

这里只复制一个有限的无环模板及步骤列表，没有实现任意对象图克隆。
若以后增加循环引用、共享子对象或资源句柄，需要重新定义复制语义。
深拷贝增加分配成本，连接、线程、锁等资源不应盲目复制。
复制期间没有并发写入保护，本示例不声称提供并发一致快照。

## 运行

设置 JAVA_HOME 为 JDK 1.8，在仓库根目录执行：

```bash
./mvnw -f patterns/creational/prototype/pom.xml test
./mvnw -f patterns/creational/prototype/v1-naive/pom.xml test
./mvnw -f patterns/creational/prototype/v2-refactor/pom.xml test
./mvnw -f patterns/creational/prototype/v3-pattern/pom.xml test
```

全项目回归：`./mvnw test`。每个叶子模块可独立运行，无需先安装其他版本。
请先阅读测试上方期望，再对照类名、方法名、结果及异常路径。
