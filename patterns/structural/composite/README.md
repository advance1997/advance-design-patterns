# 组合模式：催收材料归集目录树

诉讼案件材料按“身份材料”“履约材料”等目录分组，目录下既可放材料，也可继续放子目录。示例只使用内存对象，不连接数据库、不调用远程服务。

## 版本演进

| 版本 | 实现 | 观察重点 |
| --- | --- | --- |
| v1-naive | 服务分别递归处理目录并单独处理材料 | 调用方需识别叶子与目录，目录层级增加时分支散落 |
| v2-refactor | 把目录递归职责放进目录类，但材料与目录仍是不同类型 | 递归收敛了，调用方仍然需要区分节点类型 |
| v3-pattern | MaterialNode 统一抽象，材料是叶子，目录是组合对象 | 客户端以相同方法处理叶子和任意层级目录 |

核心结构：

```text
MaterialNode
├── MaterialLeaf（材料）
└── MaterialGroup（目录，包含多个 MaterialNode）
```

打印树结构并统计必需材料数量是本例唯一的业务观察点，用来展示统一接口和递归组合。测试各版本只有一个打印式用例，标注期望路径，不使用断言。

```bash
mvn -f patterns/structural/composite/pom.xml test
```

源码兼容 JDK 1.8；每个版本独立编译和运行。
