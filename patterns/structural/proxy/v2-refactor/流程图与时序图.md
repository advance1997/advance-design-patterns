# 代理模式：v2-refactor 流程图与时序图

本图对应版本说明：StaticTransactionProxy；手工实现同一接口，在目标调用前后包事务。

## 代码流程图

```mermaid
flowchart TD
    A[ProxyTest.testSuccess 测试入口]
    A --> B[DemoDatabase.getDataSource 业务入口]
    OP1[StaticTransactionProxy.assign 后续测试操作]
    B --> OP1
    OP2[DemoDatabase.snapshot 后续测试操作]
    B --> OP2
    Z[返回测试用例并打印实际路径]
    B -. 调用完成 .-> Z
```

## 代码时序图

```mermaid
sequenceDiagram
    participant Test as ProxyTest
    participant Entry as DemoDatabase
    participant Output as 测试输出
    participant Part1 as StaticTransactionProxy
    Test->>Entry: getDataSource()
    Test->>Part1: assign() 后续操作
    Part1-->>Test: 返回处理结果
    Test->>Entry: snapshot() 后续操作
    Entry-->>Test: 返回处理结果
    Entry->>Output: 打印执行路径与期望结果
    Output-->>Test: 输出实际结果
    Entry-->>Test: 返回业务结果
```

## 阅读提示

- 先从 `ProxyTest.testSuccess()` 进入，再沿图中的真实类名和方法名阅读源码。
- 本版本的模式关注点：代理在客户端与目标对象之间控制访问，并可承载事务等横切边界。
- 条件分支与返回细节请结合图中方法源码和同目录测试用例观察。
